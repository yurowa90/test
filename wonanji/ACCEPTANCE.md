# 완료 기준과 검증 결과

요구사항을 **완료 기준**으로 바꾸고, 실제 파일로 확인한 결과입니다. 초점은 “다양한 형태·형식의 문항을 모아 **일관되고 편집 가능한** 원안지로 취합”하는 것입니다. (검증일 2026-09-29, 커밋 기준 `claude/exam-question-template-app-3lmz0r`)

다시 확인하는 법
- 단위 테스트: `npm test` (합성 픽스처 32건)
- 실제 파일 취합: `npx tsx scripts/e2e.ts <양식.hwp> <출제…> --out out/x` → 문항 수·쪽수·재열기 검증·검수 목록
- 취합 일관성: `npx tsx scripts/check-merged.ts out/x/merged.hwpx` → 글꼴·크기 분포, 그림·표·수식 수, 구조 검증
- 사진 인식 점검: `npx tsx scripts/ocr-try.ts 사진.png --debug` → 찾은 선·동그라미·그림·글자 위치를 겹친 그림

## 1. 취합의 일관성 (핵심)

| 완료 기준 | 검증 | 결과 |
|---|---|---|
| 형식이 다른 출제 파일(HWP·HWPX·PDF·사진)이 **같은 흐름**(HWPX → 문항 분할 → 서식 통일 → 조립)을 거쳐 한 원안지가 된다 | 학교 양식 + A.hwp + 수능 PDF + 시험지 사진을 한 번에 취합 | ✅ 선택형 52·논술형 2, 12쪽, HWP·HWPX 다시 열기 통과 |
| 본문 글자 모양이 양식 값으로 통일된다(본문·〈보기〉·표 안) | `check-merged`: 글자 모양 분포 | ✅ 혼합 취합의 97.6%가 양식 본문(신명 중명조 11pt). 나머지는 양식 머리 표(맑은 고딕)·논술형 머리(12pt)·기호 글꼴 |
| 〈보기〉 상자·표·그림이 양식의 폭 규격에 맞는다(줄이거나 폭 조정) | 상자 폭 = 양식 예시 폭, 넘치는 개체 축소, 표 폭은 글자 비율로 조정 | ✅ 변경 로그 ‘크기’ 항목, 넘치면 검수 ‘개체 크기’로 알림. 단위 테스트(〈보기〉 폭 26000) |
| 문항 번호는 양식의 방식으로 1번부터 이어 붙는다(개요 번호·문단 번호·‘1.’ 글자) | 학교 양식(개요 번호), 학평 양식(개요 번호 + 번호 뒤 한 칸), 글자 번호 양식(픽스처) | ✅ 세 방식 모두 테스트·실파일 통과 |
| 결과는 **글자로 편집 가능**하다(PDF·사진도 글자를 그림으로 넣지 않음) | 합친 파일의 글자 수·그림 수 | ✅ 혼합 취합: 글자 13,763자, 그림 37개(그림·그래프만), 수식 44개 |
| 배점·정답·번호 중복이 한눈에 드러난다 | 검수 항목 | ✅ 파일별로 같은 번호가 있으면 ‘번호 중복’, 배점 합계, 정답 분포·연속 |

## 3. 학력평가 스타일 양식·출제 파일

| 완료 기준 | 결과 |
|---|---|
| 학평 문제지를 양식으로 올려도 번호가 붙고 글이 표와 겹치지 않는다 | ✅ hakpyeong.hwp + B/C: 13+1문항, 번호 ‘1. ’(양식대로 한 칸), 첫 문단은 구역 정의만 남김(1번 예시 누출 없음) |
| 학평 문제지를 출제 파일로 올리면 문항을 나눈다 | ✅ template.hwp + hakpyeong.hwp: 20문항 |
| 배점 표기가 없는 2점 문항 관례를 양식에서 읽는다 | ✅ ‘배점 표기 없는 문항 = 2점’ 옵션·검수 안내 |

원인 정리: 학평 파일은 첫 문단에 구역 정의·쪽 고정 개체·머리말이 함께 있고, 번호 모양이 “^N”이 아니라 문단 번호 뒤 공백 유무·개요 수준이 달랐습니다. “^N”은 원인이 아니었습니다.

## 아직 사람이 확인해야 하는 것

1. **한글에서 최종 확인**: 미리보기(rhwp)는 어울림 그림·표로 시작하는 문항의 번호를 그리지 않거나, 두 단에 걸친 머리 표 아래 오른쪽 단이 표와 겹쳐 보일 수 있습니다. 결과 HWP에는 번호·위치가 들어 있습니다. 이 컨테이너에는 한글이 없어 한글에서의 렌더링은 확인하지 못했습니다.
2. **배포 사이트에서 사진 업로드 1회**: 이 작업 환경은 외부 사이트 접속이 막혀 있어 배포 주소의 동작은 같은 빌드를 로컬 서버로 확인했습니다. 실제 주소에서 사진 한 장을 올려 언어 자료(`/vendor/ocr/lang/kor.traineddata.gz`)가 내려받히는지 한 번 확인해 주세요.
3. **OCR 결과의 빨간 글자**: 원본과 대조해 고친 뒤 검정으로 바꿉니다(내용을 추측해 채우지 않습니다).
