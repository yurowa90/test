# 원안지 편집기

여러 선생님이 만든 문항 파일(HWP·HWPX·PDF·사진)을 **학교 원안지 양식**에 모으고, 글꼴·글자 크기·줄간격·문단 모양·선지 배열·배점 표기를 통일한 뒤, 학교 출제 지침과 평가문항 제작 연수 자료에 비추어 **편집 검수**를 해 주는 웹앱입니다.

- 입력: 학교 원안지 양식(.hwp/.hwpx) 1개와 문항 파일 여러 개(.hwp/.hwpx/.pdf/.png/.jpg/.webp)
- 출력: 교사용 원안지 `.hwp`·`.hwpx`(정답 음영 포함), 학생 배부용 `.hwp`(선택형 정답 음영 제거), 편집 검수 보고서 `.txt`
- **시험 보안**: 모든 처리를 브라우저 안(WebAssembly)에서 하며, 파일을 어떤 서버로도 보내지 않습니다. 백엔드·데이터베이스·AI 호출이 없고, 브라우저 저장소(localStorage·IndexedDB)도 쓰지 않아 내려받은 뒤 새로고침하면 아무것도 남지 않습니다.
- **용도**: 평가 점수에 들어가는 정기시험 문항 편집이 아니라 형성평가·모의고사 제작용으로 사용해 주세요.

## 사용 순서

처음이라면 첫 화면의 **‘예시 파일로 해 보기’**로 합성 양식과 두 선생님 파일을 채워 전체 흐름을 먼저 볼 수 있습니다.

1. **양식**: 유의사항·예시 문항이 들어 있는 학교 양식을 그대로 올립니다. 앱이 양식의 구역(머리 표, 유의사항, 예시 문항, 논술형 안내, 확인 사항)과 편집 규격(본문 글자 모양, 줄간격, 문항 번호, 단 폭)을 읽고, 유의사항 문구(“글씨체: 신명 중명조”, “줄간격: 160” 등)와 예시의 실제 서식이 다르면 알려 줍니다.
2. **문항 파일**: 파일을 모두 올립니다. 합치는 방식은 두 가지이고 앱이 먼저 고른 뒤 3단계에서 바꿀 수 있습니다.
   - **선생님별 번호 분담**: 각자 자기 번호에만 문항을 쓰고 나머지 번호는 빈 개요 번호로 비워 둔 파일. 원래 번호순으로 모으며, 파일끼리 번호가 겹치면 오류로 알립니다.
   - **출처별로 이어 붙이기**: 각 파일이 1번부터 시작하는 독립 문항 묶음(예: 기출 PDF + 자작 HWP). 파일 순서대로 이어 붙이고 번호를 새로 매깁니다(순서는 ↑↓로 조정).
   빈 자리, 양식 머리 표, 확인 사항은 자동으로 뺍니다.
3. **문항·정답**: 순서를 바꾸거나(결과 번호를 눌러 새 번호 입력) 뺄 문항을 고르고, 정답(한꺼번에 붙여 넣기 가능)과 배점이 없는 문항의 배점을 넣습니다. 번호 중복·누락, 같은 문항이 두 출처에 들어간 경우(‘중복 문항 의심’), 배점 합계, 정답 분포를 바로 보여 줍니다. 사진 문항은 원본 사진을 옆에 두고 인식한 글을 문단별로 고칠 수 있습니다. ‘작업 저장(.json)’으로 설정을 내려받아 두었다가 같은 파일을 다시 올린 뒤 불러올 수 있습니다(서버·브라우저 저장소를 쓰지 않으므로).
4. **편집 옵션**: 양식에서 읽은 값으로 채워져 있습니다.
5. **원안지 만들기**: 미리보기, 편집 검수(심각도·규칙별로 거르기, 문항 번호를 누르면 그 쪽으로), 내려받기. 만든 뒤 문항·옵션을 바꾸면 내려받기를 잠그고 다시 만들도록 안내합니다.

## PDF·사진 문항 파일

| 입력 | 처리 |
|---|---|
| PDF(글자 정보가 있는 것) | pdf.js로 글자·선·그림 위치를 읽어 단·문항·〈보기〉 상자·표(병합 칸 포함)를 복원하고, 글자는 **입력한 글**로, 그림·그래프는 **잘라 낸 이미지**로 넣습니다. 분수는 한글 수식으로. |
| 사진·캡처(PNG·JPEG·WebP) | 기울기 바로잡기 → 단 나누기 → Tesseract(한국어) 인식 → 모양으로 동그라미 기호(①~⑳, ㉠, ⓐ, ○)와 선지 자모(ㄱ·ㄴ·ㄷ·ㄹ·ㅁ) 판별 → 의심스러운 로마자만 영어로 다시 인식 → PDF와 같은 레이아웃 복원 |

- **인식이 불확실한 글자는 결과 파일에 빨간색**으로 남기고, 편집 검수에 ‘글자 인식 확인’으로 문항마다 알립니다. 내용을 추측해 채우지 않습니다.
- PDF·사진에는 형광펜 정보가 없으므로 정답은 3단계 화면에서 지정합니다(결과에 음영으로 표시).
- 인식 엔진(tesseract.js)·한국어/영어 자료·pdf.js 글꼴은 모두 이 사이트에서 제공합니다(`scripts/copy-assets.mjs`가 빌드 때 `public/vendor`로 복사). 외부 CDN으로 파일을 보내거나 받지 않습니다.
- 점검: `npx tsx scripts/ocr-try.ts 사진.png --debug` — 찾은 선·동그라미·그림·글자 위치를 겹친 그림을 `out/`에 저장합니다.

## 처리 원리

```
HWP/HWPX ─rhwp(WASM)→ HWPX(XML) ─┬─ 형광펜 복원(HWP 바이너리의 영역 태그를 직접 읽음)
                                 ├─ 양식 분석: 구역·규격·유의사항 규칙
                                 ├─ 문항 파일 분할: 개요 번호/【문항n-논술형】/빈 자리/양식과 같은 문단
                                 ├─ 조립: 양식 사본에 문항 XML을 그림·표·수식째 옮기고
                                 │        글자·문단 모양 ID를 양식 기준으로 다시 매김(서식 통일)
                                 └─ 출력: HWPX(줄 배치 캐시 제거) / HWP(rhwp 변환 후 캐시 제거) / 미리보기 SVG
```

문항 내용(글자)은 앱이 스스로 바꾸지 않습니다. 자동으로 고치는 것은 배점 표기, 번호, 문단 앞 공백처럼 **형식**에 한정되며, 모든 변경 내역이 “자동으로 고친 것”에 남습니다. 교사가 직접 한 편집(배점 입력, ‘양식 기호로 바꾸기’, 사진 문항 글자 고침)만 글자를 바꾸며, 이것도 변경 로그와 검수 보고서에 남고 3단계에서 되돌릴 수 있습니다.

## 설계 결정과 그 근거

- **정답 형광펜 → 글자 음영.** rhwp의 HWPX 내보내기는 형광펜(HWP 영역 태그)을 옮기지 않고, HWPX에 넣은 형광펜 표지도 읽지 못합니다. 그래서 원본 HWP 바이너리의 `PARA_RANGE_TAG`를 직접 읽어 같은 글자에 **음영**을 입힙니다. 인쇄물에서는 형광펜과 같게 보이고 HWP·HWPX 모두에 남습니다. 이때 탭이 8 WCHAR를 차지한다는 규격대로 위치를 계산해야 하며, 실제 파일에서 모든 형광펜 구간이 원문자(①~⑤) 위에 정확히 떨어지는 것으로 검증했습니다(rhwp 화면 표시는 탭을 1칸으로 세어 형광펜이 어긋나 보입니다).
- **줄 배치 캐시.** 서식을 바꾸면 원본의 줄 배치 캐시(linesegarray/PARA_LINE_SEG)가 낡습니다. 내려받는 파일에서는 캐시를 모두 지워 한글이 열 때 다시 계산하게 합니다. 반면 rhwp는 캐시가 없으면 그림이 든 문단·떠 있는 개체를 잘못 배치하므로, 미리보기와 HWP 변환에는 원본 캐시를 둔 사본을 씁니다.
- **자간·장평은 기본으로 유지.** 선생님들이 〈보기〉 한 줄을 맞추려고 줄인 자간을 없애면 줄이 넘칩니다(실제 파일에서 확인). 학교 지침도 자간 조정을 편집 기법으로 안내합니다.
- **그림 배치용 표는 글꼴만 바꿉니다.** 그림과 캡션을 담은 표의 줄간격을 바꾸면 그림 자리가 흐트러지기 때문입니다. 그림이 든 문단, 표 안의 빈 칸도 원래 간격을 지킵니다.
- **부정어 표시 방식은 옵션.** 양식 유의사항은 “밑줄, 진하게”, 학교 「정기시험 문항 제작 및 출제 유의사항」은 “밑줄만 긋고 ‘굵게’ 표시하지 말 것”으로 서로 다릅니다. 기본값은 양식을 따르고 화면에 충돌을 표시합니다.

## 한계(꼭 한글에서 최종 확인)

- 이 저장소의 검증은 rhwp로 다시 열기·구조 검증(모든 ID 참조 확인)·실제 문항 파일 3개 병합까지입니다. **한컴오피스 한글에서 연 결과는 아직 확인하지 못했습니다.**
- 미리보기(rhwp)는 한글과 다를 수 있습니다: ‘다음 문단과 함께’ 미반영으로 쪽 끝에서 문항이 잘려 보이는 현상. 두 단에 걸친 머리 표와 첫 쪽 오른쪽 단이 겹치는 현상은 미리보기용 사본에만 빈 칸을 넣어 한글처럼 그리도록 보정했습니다(내려받는 파일은 그대로, 보정하지 못한 양식은 화면에 그렇다고 표시).
- 표 형식 선지(A/B 칸 맞춤), 그림이 든 선지는 다시 배열하지 않고 그대로 둡니다.
- 차트·OLE 개체, 쪽(용지) 기준으로 고정된 개체, 여러 구역으로 된 양식은 결과를 확인해야 합니다. 암호·배포용 문서는 읽지 않습니다.
- 발문 규칙 검수는 문자열 규칙이라 놓치거나 과하게 잡을 수 있습니다(예: 부정어는 물음표 앞 24자 안에서만 찾습니다).

## 개발

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 합성 문서로 엔진·작업 저장 전체 점검 49건(실제 시험 파일 불필요)
npm run build      # 타입 검사 + 정적 빌드(dist/)
npx tsx scripts/e2e.ts 양식.hwp 출제1.hwp 출제2.hwp --out out   # 로컬 실제 파일로 전체 흐름
npx tsx scripts/validate.ts out/merged.hwpx                        # 결과 HWPX 구조 검증
```

`samples/`, `out/`, `*.hwp`, `*.hwpx`는 `.gitignore`에 들어 있습니다. **실제 문항 파일·원안지는 저장소에 올리지 마세요.**

배포: Vercel은 Root Directory를 `wonanji`로 지정하고(`vercel.json` 포함), Netlify는 Base directory를 `wonanji`로 지정합니다(`netlify.toml` 포함). rhwp WASM(약 9.9MB, gzip 3.7MB)은 처음 파일을 열 때 한 번 내려받습니다.
