# 기존 문항·자료 개선

화면 상단 ‘기존 문항·자료 개선’에서 기출문제, 교과서·전공서적, 논문, 아이디어를 입력한다. 텍스트 붙여넣기와 PDF·PNG·JPEG·WebP 첨부를 지원한다. 앱은 최대 3개·원본 합계 8MB로 제한한다. 큰 자료는 사용할 페이지만 추리고 읽을 쪽수·문항·그림 번호를 지정한다. URL만으로 원문을 검색하거나 가져오지는 않는다.

1. 원자료를 구조화한다. 판독하지 못한 수치·기호는 추정하지 않도록 지시한다. 원문의 직접 발문 전체와 선택지 배열은 판독 노트에 남기고, 앱의 자료 소개·직접 발문 앞부분·자료·조건·진술로 나눈다.
2. 교사가 읽기 결과를 원문과 대조하고 수정한다. 첨부 자체는 자동 저장하지 않으며, 읽기 결과와 텍스트·수정안은 브라우저에 저장한다.
3. 발문, 자료(그림·표·그래프 포함), 보기·선택지 중 바꿀 부분을 선택한다. ‘다듬기’, ‘변형’, ‘아이디어 문항화’를 구분한다. 선택하지 않은 부분은 코드에서 원문으로 고정한다.
4. 원본·수정안·이유·다른 문항에 적용할 원리·재검토 사항을 비교한다. 그림은 기존 SVG 렌더링·편집 기능을 재사용한다. 직접 고친 경우 진위를 판단보류로 되돌린다.
5. 진위와 근거의 보류를 해결한 뒤 현재 작업을 보관하고 기존 3단계로 가져온다. 기존 정답 번호를 승계하지 않고 선택한 유형으로 재계산한다. 명제 확인 및 교사 최종 승인은 다시 수행한다. 이때 행동 영역·수행 수준은 초기값이므로 실제 문항에 맞게 검토해야 한다.

원자료 수치를 보존하는 모드와 아이디어 기반 합성 모드를 구분한다. 확인한 출처 위치와 원문 발췌를 문항 출처 기록에 연결하며, 원자료에 없는 그래프 수치는 가져오기 전에 차단한다. 이 검사는 과학적 의미·단위 대응·저작권 이용 조건을 자동 승인하지 않는다.

개선 기록은 별도로 다운로드하거나 가져온 문항의 성장 노트·교사용 출력에서 확인할 수 있다. 원문과 수정안 기록은 학생용 문항에 포함하지 않는다.

첨부는 읽기 실행 시 현재 Gemini 모델에 inlineData로 전송하며 기존 오류·재시도·할당량·인증 경로를 그대로 사용한다. 별도 키를 만들지 않는다. Google 공식 API의 [generateContent 입력](https://ai.google.dev/api/generate-content)과 [PDF 처리 문서](https://ai.google.dev/gemini-api/docs/document-processing)를 확인하여 구현했다. 실제 모델의 판독·수정 품질은 교사 검토가 필요하다.
