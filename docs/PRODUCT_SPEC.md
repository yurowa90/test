## 1. 제품 개요

한국 중·고등학교의 **독서교육**과 **과학교육**을 위한 AI 학습 대화 플랫폼.

- 교사가 학습 목표·AI 역할·루브릭을 설정하여 AI 수업을 설계한다.
- 학생은 회원가입 없이 **수업 링크 또는 참여 코드 + 닉네임**만으로 참여한다.
- 학생은 AI와 1:1 학습 대화를 한다. AI는 정답을 바로 주기보다 질문과 피드백으로 사고를 확장한다.
- 모든 학생-AI 대화는 Supabase에 저장된다 (Source of Truth).
- 교사는 대시보드에서 학생들의 대화와 사고 흐름을 실시간으로 관찰한다.
- 수업 종료 후 AI가 루브릭 기준으로 대화를 분석하여 **근거(message 단위)가 연결된 평가**와 피드백 초안을 생성한다.
- 교사가 AI 평가·피드백을 검토·수정·확정한다. AI는 초안 작성자, **최종 평가자는 교사**다.
- Gemini API 비용은 운영자가 아닌 교사가 부담한다 (**BYOK**: Bring Your Own Key).

## 2. 해결하려는 문제

| 문제 | 현재 상황 | 본 제품의 접근 |
|---|---|---|
| 사고 과정 추적 불가 | 교사 1명이 학생 30명의 사고 과정을 수업 중 개별 확인할 수 없음 | 모든 대화가 저장되고 대시보드에서 학생별 사고 흐름을 열람 |
| 일반 챗봇의 한계 | ChatGPT류는 정답을 즉시 제공 → 탐구·독해 훈련에 역효과 | 소크라틱 전략(명료화·근거 요구·반례 등) 중심의 교육 특화 대화 설계 |
| 평가 부담 | 대화형 수업은 채점 근거 수집과 개별 피드백 작성 부담이 큼 | AI가 루브릭 기반 평가 초안 + 실제 대화 근거를 생성, 교사는 검토·확정만 |
| AI 평가 불신 | 근거 없는 점수는 교사·학생 모두 신뢰하지 않음 | 모든 평가 항목이 실제 message_id에 연결, 교사 확정 전에는 비공개 |
| 개인정보 부담 | 학생 계정 생성은 학교 현장에서 큰 행정·법적 부담 | 익명 인증 + 닉네임만 수집 (개인정보 최소화) |
| 운영 비용 | 운영자가 API 비용을 부담하면 지속 불가능 | 교사 BYOK, 키는 영구 저장하지 않음 |

## 3. 참고 서비스 분석 — SocRoom (https://soc.codle.io/)

SocRoom의 수업 생성 화면(2026-08 기준 스크린샷)에서 확인된 설정 항목과 본 제품의 채택 여부:

| SocRoom 기능 | 내용 | 본 제품 방침 |
|---|---|---|
| 학습 주제 — 직접 입력 | 텍스트로 주제 입력 | **채택 (MVP)** |
| 학습 주제 — PDF 업로드 | 자료 기반 수업 | 보류 (post-MVP, PHASE 12 이후 후보) |
| 학습 주제 — 링크로 등록 | URL 자료 등록 | 보류 (post-MVP) |
| 학생 응답 횟수 제한 | 슬라이더 5~20회 | **채택** — `lessons.max_student_messages` (기본 20, 범위 5~50). 비용 통제 + 수업 시간 관리 |
| 학습 난이도 | 쉬움/보통/어려움 | **채택** — 난이도가 AI 시스템 지시의 어휘 수준·힌트 제공 정도를 조절 |
| 학생 점수 보기/숨김 | AI 채점 결과 학생 공개 여부 | **변형 채택** — 본 제품은 "교사 확정 전 비공개"가 기본. 공개 시에도 **교사가 확정한 피드백/점수만** 학생에게 노출 |
| 수업 이름 (선택) | 목록 표시용 이름 | **채택** — `lessons.title` |
| 링크/코드 참여 | 학생 무가입 참여 | **채택** — 참여 코드 + 링크 |

본 제품의 차별화 (SocRoom 복제가 아닌 이유):

1. **루브릭 기반 평가 체계** — 교사가 편집 가능한 criterion 단위 루브릭, 평가 근거가 실제 대화 message에 연결됨.
2. **교사 검토 워크플로** — AI 평가는 초안이며, 교사의 검토·수정·확정 단계가 제품의 1급 기능.
3. **독서·과학 특화 템플릿** — 교과 교육론에 기반한 수업 템플릿 (CER, 비경쟁 독서토론 준비 등).
4. **BYOK 구조** — 교사 소유 Gemini API Key, 키 비저장 원칙.
5. **데이터 소유권** — 대화 기록의 Source of Truth는 Supabase (Gemini 서버 저장 비의존, store=false).

## 4. 사용자 역할

### 4.1 teacher (교사)

- 인증: Supabase Auth — Google OAuth (초기), 이후 다른 OAuth 추가 가능.
- 권한: 자신이 만든 수업/학생/대화/평가/피드백 데이터만 접근 (타 교사 데이터 접근 불가 — RLS 강제).

기능 목록:

| # | 기능 |
|---|---|
| T1 | 수업(Class/Lesson) 생성·수정·삭제 |
| T2 | 참여 코드 생성 (링크 공유) |
| T3 | 학생 참여 현황 확인 (실시간) |
| T4 | 학생별 대화 확인 (실시간 관찰 포함) |
| T5 | 학생별 AI 평가 확인 |
| T6 | AI 피드백 확인·수정·최종 저장(확정) |
| T7 | 평가 루브릭 작성·수정 |
| T8 | 수업 템플릿 사용·개인 템플릿 관리 |
| T9 | Gemini API Key 입력·검증 (BYOK) |
| T10 | AI 평가 실행 (수업 종료 후 일괄) |

### 4.2 student (학생)

- 인증: **Supabase Anonymous Sign-In** — 고유 `auth.uid`는 생성되지만 이메일/비밀번호/실명을 요구하지 않음.
- 입력 정보: **수업 코드 + 닉네임** 뿐. (닉네임에 실명 입력을 지양하도록 안내 문구 표시)
- 권한: 자신이 참여한 수업의 공개 정보와 **자신의 대화 데이터만** 읽기/쓰기 가능. 타 학생 대화 접근 불가 (RLS 강제).

기능 목록:

| # | 기능 |
|---|---|
| S1 | 수업 링크/코드로 참여 (닉네임 입력 → 익명 인증) |
| S2 | AI와 학습 대화 |
| S3 | 남은 응답 횟수·진행 상태 확인 |
| S4 | (수업 설정에 따라) 교사가 확정한 피드백 열람 |

## 5. 핵심 기능 — MVP 범위

### 5.1 MVP 포함 (PHASE 1~11에서 구현)

| # | 기능 | PHASE |
|---|---|---|
| F1 | 교사 인증 (Google OAuth) + 학생 익명 인증 | 2 |
| F2 | Class / Lesson 생성·수정·삭제·상태 관리 | 3 |
| F3 | 참여 코드·링크 생성, 학생 참여(닉네임) | 3 |
| F4 | Gemini API Key Validator (`/settings/ai`) | 4 |
| F5 | 학생-AI 대화 (저장·idempotency·응답 횟수 제한) | 5 |
| F6 | 교사 대화 관찰 대시보드 (Class Overview / Student List / Student Detail) | 6 |
| F7 | 루브릭 CRUD + AI 평가 실행 (근거 message 연결) | 7 |
| F8 | AI 피드백 초안 + 교사 검토·수정·확정 | 8 |
| F9 | 독서교육 수업 템플릿 | 9 |
| F10 | 과학교육 수업 템플릿 | 10 |
| F11 | AI 사용 로그 (ai_usage_logs) | 4~7에 걸쳐 |
| F12 | 대화 요약 (conversation_summaries — 토큰 절약용) | 5 |

### 5.2 MVP 제외 (명시적 후순위)

- 학습 주제 PDF 업로드 / 링크(URL) 자료 등록
- 학생 간 점수 비교·랭킹 (교육적으로도 신중해야 함)
- 학부모용 리포트, 학교 관리자 계정, 학급 명렬표 연동
- 다국어 지원 (한국어 우선)
- 모바일 최적화 교사 대시보드 (PC 우선; 학생 화면은 모바일 대응)
- 결제·과금, 사용량 정산
- 음성 대화, 이미지 입력
- 학생 세션 유실 시 participant 병합 도구 (운영 도구로 후순위)

## 6. 수업 설정 항목 (Lesson Settings)

교사가 수업 생성 시 설정하는 항목. `lessons` 테이블 설계의 근거 (상세: DATABASE_DESIGN.md).

| 항목 | 필드 | 기본값 | 비고 |
|---|---|---|---|
| 수업 이름 | `title` | (필수) | 목록 표시용 |
| 교과 유형 | `subject_type` | — | `reading` \| `science` |
| 학습 주제 | `topic` | (필수) | 직접 입력 (MVP) |
| 학습 목표 | `goals` | (필수) | 학생 화면에도 표시 |
| AI 역할 지시 | `system_instruction` | 템플릿 제공 | 학생에게는 절대 노출하지 않음 |
| 난이도 | `difficulty` | `normal` | `easy` \| `normal` \| `hard` |
| 학생 응답 횟수 제한 | `max_student_messages` | 20 | 범위 5~50 |
| 점수 학생 공개 | `show_score_to_student` | `false` | 공개해도 **교사 확정분만** 노출 |
| 루브릭 | `rubric_id` | 템플릿 기본 루브릭 | 교사 수정 가능 |
| 참여 코드 | `join_code` | 자동 생성 | 6자리 영숫자, 활성 수업 내 유일 |
| 수업 상태 | `status` | `draft` | `draft → active → ended → archived` |

## 7. 비기능 요구사항

| 영역 | 요구사항 |
|---|---|
| 보안 | RLS 없는 public 테이블 금지. 교사 간·학생 간 데이터 격리. API Key/service role 브라우저 비노출. 상세: SECURITY_MODEL.md |
| 개인정보 | 학생은 닉네임만 수집. 실명 지양 안내. 수업 삭제 시 관련 데이터 cascade 삭제 |
| 규모 | 교사 1명 기준 학생 30명 동시 대화를 안정적으로 처리 (교실 1개 규모가 MVP 기준) |
| 비용 | BYOK + 컨텍스트 압축(요약 + 최근 N개)으로 교사 토큰 비용 통제. 응답 횟수 제한 |
| 신뢰성 | 메시지 중복 저장 방지(idempotency), 네트워크 재시도 안전 |
| 접근성 | 학생 화면은 단순·저사양 기기 대응. 교사 대시보드는 PC 우선 |
| 종속성 | 배포 플랫폼 비종속 (Node.js 호스팅 어디든). Supabase는 관리형 사용 |

## 8. MVP 성공 기준

1. 교사 1명 + 학생 30명이 45분 수업 1회를 처음부터 끝까지(참여→대화→평가→피드백 확정) 완주할 수 있다.
2. 학생 참여는 링크 접속 → 닉네임 입력 → 대화 시작까지 30초 이내.
3. 네트워크 재시도 상황에서 메시지 중복·유실 0건.
4. AI 평가의 evidence_message_ids가 100% 실제 해당 대화의 메시지를 가리킨다 (검증 로직 통과).
5. RLS 침투 테스트(교사 A↔B, 학생 A↔B 교차 접근 시나리오) 전체 통과.
6. Gemini 오류(키 오류/쿼터/네트워크)가 정규화된 한국어 안내로 표시되고, 429가 키 오류로 오분류되지 않는다.

## 9. 용어 정의

| 용어 | 정의 |
|---|---|
| Class | 교사가 만든 학급/그룹 단위 (예: "3학년 2반 과학"). 여러 Lesson을 포함 |
| Lesson | 1회 수업 단위. 참여 코드·목표·AI 역할·루브릭을 가짐 |
| Participant | 특정 Lesson에 참여한 학생 (익명 auth.uid + 닉네임) |
| Conversation | Participant 1명의 학생-AI 대화 세션 (MVP에서는 participant당 1개) |
| Message | 대화 내 발화 1건 (student / ai / system) |
| Turn | 학생 메시지 1건 + AI 응답 1건의 쌍 |
| Rubric / Criterion | 평가 기준 집합 / 개별 평가 항목 (배점 포함) |
| Evaluation | AI가 수행한 루브릭 평가 실행 결과 (criterion별 점수·근거·이유) |
| Teacher Feedback | 교사가 검토·수정하여 확정한 최종 피드백 |
| Template | 독서/과학 교육용 사전 정의 수업 설계 (AI 역할 + 기본 루브릭) |
| BYOK | Bring Your Own Key — 교사 소유 Gemini API Key 사용 구조 |
